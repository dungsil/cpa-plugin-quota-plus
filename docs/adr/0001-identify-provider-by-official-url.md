# 제공자를 공식 URL로만 판별합니다

호스트는 provider 키로만 할당량 플러그인을 고르지만, `openai-compatibility` 항목의 provider 키는 사용자가 붙인 이름(`openai-compatible-<이름>`)으로 정해집니다. 그래서 이 플러그인은 자격 증명의 base URL이 공식 URL과 같은지로만 제공자를 판별합니다. `quota.describe`는 `host.auth.list`에서 공식 URL을 가진 항목의 provider 키를 모아 `SupportedProviders`로 선언하고, `quota.fetch`는 `Attributes["base_url"]`로 제공자를 다시 정합니다. 사용자가 이름을 자유롭게 붙여도 설정 없이 동작하게 하려는 결정입니다.

## 검토한 대안

- **정해진 provider 키 이름을 요구하는 방식**: 사용자가 기존 설정의 이름을 바꿔야 하고, 이름이 다르면 아무 안내 없이 매칭되지 않습니다.
- **플러그인 설정으로 provider 키 목록을 받는 방식**: 키를 추가할 때마다 두 곳을 고쳐야 합니다.
- **provider 키 조건과 URL 조건을 함께 쓰는 방식**: 아래 부작용을 줄이지만, 위 두 방식의 불편이 다시 생깁니다.
- **키 접두사로 판별하는 방식**: 세 제공자 모두 키 접두사 규격을 공개하지 않았습니다.

## 결과

- `claude-api-key`처럼 provider 키가 고정값인 항목에 공식 URL이 하나라도 있으면, 그 provider 키(예: `claude`)를 가진 모든 자격 증명의 할당량 요청이 이 플러그인으로 옵니다. 공식 URL이 아닌 자격 증명은 오류가 됩니다.
- 같은 provider 키를 선언한 다른 할당량 플러그인이 있으면 호스트가 먼저 찾은 플러그인만 쓰입니다.
- 공식 URL과 조금이라도 다른 주소(OpenCode Zen, 로컬 Ollama, 프록시 주소)는 대상이 아닙니다. 이 판별 방식을 나중에 바꾸면 사용자의 기존 설정이 매칭되지 않을 수 있으므로 되돌리기 어렵습니다.
